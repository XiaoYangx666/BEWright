# Minecraft 手动验收

本文是验收流程，不声明任何建筑已通过。每次交付从“游戏内未验证”开始记录；文件生成、静态检查和预览通过都不等于客户端加载通过。记录主菜单实际版本（工具目标 Bedrock 1.21.60 / Java 26.1.2；其他版本单独记录）。

## 直接写入世界后的验收（默认路径）

按执行流程完成写入，记录世界路径。已有 Bedrock 存档追加或覆写时，同时记录导入范围及备份路径。 [执行流程](agent-workflows.md)

1. 用对应版本客户端打开该世界，确认列表名称和实际目录对应；记录加载成功或完整错误。
2. 确认出生位置、朝向、建筑位置、地形和边界；检查水、玻璃、楼梯、门、围栏与灯具的实际状态。
3. 分别观察外观与室内：入口可进入、楼层可到达、楼梯净空足够、关键房间有实际用途。预览的自由飞行不能证明玩家通行。
4. 保存整体、入口、室内和关键路线的游戏截图，逐项记录通过或待修复。

用清单导入时，逐处确认坐标和朝向，并检查景点间通行。覆写已有世界时，查看重叠处、预期清空处，以及邻近应保留的方块和设施。

双版本交付分别执行，不以某一版本通过代替另一版本。没有游戏操作能力或用户要求等待实测时，报告世界已写入及其路径，并保留游戏内未验证状态。

## 结构方块导入（仅交付 `.mcstructure` 时）

使用新建创造测试世界并启用作弊。直接写入世界不需要重复此导入流程。

Windows 结构方块手动流程：使用 `/give @s structure_block`，放置结构方块，切换 Load，Import 选择生成的结构文件。加载时关闭旋转、镜像和实体，完整度 100%，确认预览框原点。所有坐标都相对实际加载框最小点 O；不要将文件里的 `structure_world_origin` 当作强制目标位置。

导出默认是布局版本 1，兼容范围较广；仍须在实际目标客户端验证；`--structure-version 2` 使用 IntArrayTag 并省略空的第二层，实际文件大小随模型变化，但**只能**在 Bedrock 26.50（1.26.50）及以上加载，验收前先记录客户端版本。加载成功后另存一次会把 v1 文件升级成 v2（游戏自身行为）。

## 准备文件

```powershell
node dist/cli/index.js build demo-arch --export
node dist/cli/index.js preview demo-arch --all-views # 生成声明视图截图
# 仅在需要注册表专项回读诊断时：
# node dist/cli/index.js registry verify
```

## 1. 空气与坐标哨兵

若已执行注册表专项诊断，`artifacts/block-gallery.mcstructure`（15×4×11）包含 12 种代表性方块与一个双层门。加载前在 O 附近放明显哨兵方块，加载后确认：底座为 smooth_stone、样本方块按图排列、门占两格高、未写入的位置不被清除（Void 保持语义）。

## 2. 拱门整体

`examples/demo-arch/output/bedrock/demo-arch.mcstructure`（9×8×7）。在空旷区域加载，核对地板、两根柱子和横梁，再以玩家视角穿过中央开口。与本次 `preview` 的截图比对。模型中未设置的格会保留加载位置的原方块。

## 3. 可选：回读比对

正常验收只需要在游戏里看，**默认不回读**（工具也不再提供结构文件回读的 CLI 入口）。怀疑文件损坏或需要留存证据时，切换 Save 另存为 `*-saved.mcstructure`，再用独立解析器（例如 `bewright registry verify` 用的同一条 `nbtify` 路径，或临时脚本）逐位置比较名称与状态。

## 4. Java 侧

```powershell
node dist/cli/index.js export demo-arch --edition java --name "拱门验收"
```

用 26.1.2 客户端加载，确认世界出现在列表、地形为超平坦、建筑位置与坐标一致。脚本化核验（`level.dat`、`world_gen_settings.dat`、Anvil 区块坐标与区段数）直接用 `cache/sidecar/` 下的 `blockwright-java-export` / `blockwright-world-diagnose`，CLI 不再包装。

## 验收记录

每个版本独立保存以下记录；未执行的项写“未检查”，不要写“通过”。

| 字段 | 内容 |
|---|---|
| 模型 | 建筑 id、参数、源码版本及未提交改动说明 |
| 交付 | 日期、版本、世界绝对路径、写入结果或导入提示 |
| 坐标 | 放置原点、旋转、出生点；Java 记录模型原坐标 |
| 客户端 | 实际版本、世界设置、加载结果或错误 |
| 观察 | 外观、室内、通行、关键方块状态各自结论 |
| 证据 | 当前世界的游戏截图路径；结构方块测试另附空气哨兵结果 |
| 状态 | 游戏内未验证 / 验收发现问题 / 本次检查项通过，以及尚未检查的范围 |
